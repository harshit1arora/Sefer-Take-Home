# Approach (one page)

**What it does.** One app: a React workspace (the supplied design, unchanged in layout) talking to an Express API. PDFs are uploaded as multipart `documents`; the backend sends them to a model as native PDF documents (text layer and page images, so scans work; Tesseract was tried on the two scans and rejected), validates the returned JSON with Zod, reconciles the documents, and builds the XML **deterministically** (no model writes XML) in the element order of NetCHB's `entry.xsd`. The XML is validated for well-formedness and against the XSD, and the response says exactly which schema was used.

**Value integrity.** Extracted values are never overwritten. The entered value is a sum of components, each tagged `source`, `derived`, `suggested` or `broker_approved`. For the sample it is **22,899.00** from printed amounts only. Two suggestions are listed but excluded until a broker ticks them: **+360.00** on the T-shirt line (printed 6,480.00 vs 2,400 x 2.85 = 6,840.00; the invoice's own carried-forward subtotal, FOB and CIF totals agree with 6,840, but a unit price of 2.70 would also reproduce 6,480, so the documents do not prove which was paid) and the **4,180.00** buyer-supplied-fabric assist, kept apart from the 1,260.00 blouse amount. Approving both gives 27,439.00. Freight 3,850.00 and insurance 185.00 are excluded (CIF). Edits made in the UI are applied to a copy of the original extraction and recorded; a changed amount becomes a separate broker override next to the printed value.

**Findings kept visible.** T-shirt amount mismatch; hoodie quantity (invoice 1,200 vs packing list 1,176, a 24-piece gap equal to the sample quantity, flagged only as a hypothesis); B/L vs packing-list gross weight (1,930 vs 1,888 kg); mixed origin with the Bangladesh samples; free-of-charge samples; the hand-corrected container number (printed OPLU1041726 fails its ISO 6346 check digit, handwritten OPLU1041723 passes; carrier confirmation requested); invoice number rewritten from `HLAS/BP/26-0912` to `HLAS-BP-26-0912` because the XSD forbids slashes; missing importer ID, bond, processing port and 10-digit HTSUS codes (never guessed; the XML carries a visible `0000` processing-port placeholder).

**Honest status.** The response always carries `readiness`: not ready to file while blocking inputs, unconfirmed assumptions, suggested changes or document errors remain. XSD validity is labelled structure-only, the NetCHB check is permanently "unavailable" (nothing is submitted), and a pass against the bundled subset schema is labelled partial. `npm run fetch-schemas` downloads the official files and self-verifies them; only then does the app call the check complete.

**Model configuration.** The extraction model is configurable through `GEMINI_MODEL`. The default is a **documented** Gemini API id (`gemini-3.8-flash`), never a fabricated one; a value that is not a `gemini-<model-id>` id is ignored with a warning and the default is used, and the effective model is reported by `/api/health` and at startup.

**What was and was not verified (see `docs/FINAL-VERIFICATION.md`).** Latest run (2026-10-18): clean install; **94 backend tests** (93 passed, 0 failed, 1 opt-in live test skipped) and **27 frontend tests** under real `vitest`+`jsdom`; typechecks for frontend and server; production build; all sample XML against the bundled subset schema. A **live Gemini extraction** (`gemini-3.8-flash`) of the three real PDFs was performed on **2026-10-11** and returned the correct values (entered 22,899 / 27,439) with a schema-valid XML; it was **not** re-run in the latest pass. Earlier recorded totals (e.g. 67 backend tests) are historical and superseded. **Not verified:** the full official schema (`npm run fetch-schemas` could not reach the schema host) and a real-browser run (exercised at the HTTP layer and through the live API instead). The packing list and B/L are scans; the live run read them from the PDF page images.

**Assumptions to confirm (listed in the app).** Entry type 01, mode 11, SCAC/number split of bill numbers, header `charges`, Cat Lai port code (55224 vs 55225), country of export for the samples, sample valuation, MIDs derived from the CFR rule, B/L weight preferred over the packing list.

**With more time.** Run the live extractor on many synthetic layouts and score it field by field; validate against the full XSD in CI; an HTS suggestion step (candidates with rulings, shown as suggestions only); a broker review screen with per-field approval history; ACE party blocks and PGA sections; sandbox submission behind explicit human approval and authentication for the API.
